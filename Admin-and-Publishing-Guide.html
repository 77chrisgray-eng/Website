2. Information to collect from the church

  • Street address and ZIP; main phone; a phone that can receive texts; office email; optional prayer email; office hours
  • Confirmed service times (Sunday school, worship, Bible study, prayer meeting)
  • The church's original logo (PNG, ideally with a transparent background) and good photos: building, sanctuary, choir, events (JPG, under 500 KB each is best)
  • History, founding date, milestones, mission, vision, statement of faith — exactly as approved by the church
  • Pastor's name, title, biography and photo; leadership names and roles
  • Ministry descriptions, leaders and meeting times
  • Facebook, YouTube, Instagram links; YouTube channel ID
  • Which people may receive counseling, transportation and prayer submissions
  • Giving provider decision

3. Publish the website — using only an iPhone (free, with HTTPS)

Recommended: GitHub Pages. It's free, includes HTTPS automatically, and lets you edit the site later right in Safari. Allow about 20 minutes.

A. Unzip the files

  1. Save JordanRiver-Website.zip to the Files app (tap the file → Share → Save to Files).
  2. In Files, tap the zip once. iPhone creates a folder named JordanRiver-Website. Inside is a website folder — that holds the site files.

B. Create a free GitHub account and upload

  1. In Safari go to github.com → Sign up. Use a church email, not a personal one, so the account stays with the church. Pick a username such as jordanriverbuffalo.
  2. Tap the + (top right) → New repository. Name: website. Choose Public. Check Add a README file. Tap Create repository.
  3. Tap Add file → Upload files → choose your files → Browse → open the website folder → tap Select (top right) → Select All → Open. (Tip: if the page looks cramped, tap aA in the address bar → Request Desktop Website.)
  4. Wait for all files to finish uploading. You should see 21 files, including index.html, config.js, main.js and style.css. Scroll down and tap Commit changes.

C. Turn on the free website

  1. In the repository, tap Settings (use Desktop Website if you don't see it) → Pages.
  2. Under Build and deployment, Source: Deploy from a branch. Branch: main, folder /(root) → Save.
  3. After 1–2 minutes, refresh. The page shows the live address, e.g. https://jordanriverbuffalo.github.io/website/. It's already secure (HTTPS). That is the free web address you can share right away.
Alternative — Cloudflare Pages (also free, also HTTPS): sign up at dash.cloudflare.com → Workers & Pages → Create → Pages → Upload assets → name the project → upload a zip of the files in the website folder → Deploy. You get https://yourproject.pages.dev. Updates mean uploading a new zip each time, so GitHub is easier for regular editing. Cloudflare also uses the included _headers security file.

4. Connect JordanRiverBuffalo.com

A custom .com is not free. Free hosts give you a free address like …github.io instead. I couldn't check whether JordanRiverBuffalo.com is still available. Search for it at domains.cloudflare.com. Cloudflare Registrar sells domains at cost with no markup on renewals (roughly $10–11 a year for a .com).

  1. Buy the domain at Cloudflare (or any registrar). Register it to the church, using the church email.
  2. In Cloudflare: open the domain → DNS → Records → add four A records, name @, pointing to 185.199.108.153, 185.199.109.153, 185.199.110.153, 185.199.111.153. Set the proxy (orange cloud) to DNS only (grey).
  3. Add a CNAME record: name www, target YOURUSERNAME.github.io (DNS only).
  4. In GitHub → repository → Settings → Pages → Custom domain: type jordanriverbuffalo.com → Save. When the check passes, tick Enforce HTTPS. The certificate can take up to 24 hours.
  5. If you use a different address, change websiteUrl in config.js and the addresses in sitemap.xml and robots.txt.

SEO: once the site is live, add it to Google Search Console (free) and submit sitemap.xml. Also claim or update the church's free Google Business Profile so it shows up in Maps.

5. Turn on the forms (free — Web3Forms)

  1. Go to web3forms.com, enter the email address that should receive submissions, and tap Create Access Key. The key is emailed to you.
  2. Edit config.js (see Section 11). Paste the key between the quotes of accessKey: "".
  3. Keep counseling confidential: create a second key using the pastor's private email and paste it into counselingKey. Do the same for transportationKey (transportation coordinator) and prayerKey if you like. Any you leave blank use the main key.
  4. Test every form after publishing: submit a test on each page and confirm the email arrives. Don't announce the forms until they've been tested.

Built-in protections: required-field checks with clear messages, a hidden anti-spam field, confirmation and error messages, and an honest “NOT sent” message if a form isn't connected or the internet fails.

6. Event calendar (free — Google Calendar)

  1. Using the church Google account, open Google Calendar (on iPhone use Safari at calendar.google.com with Desktop Website). Create a new calendar named “Jordan River Events”.
  2. Calendar Settings → Access permissions → Make available to public (see all event details). Never put private information in event descriptions.
  3. Under Integrate calendar, copy the Calendar ID (ends in @group.calendar.google.com). Paste it into googleCalendarId in config.js. That alone shows Google's calendar on the Events page (Option A).
  4. Option B (recommended look): at console.cloud.google.com create a free project → enable Google Calendar API → Credentials → Create API key. Restrict it to Google Calendar API and to Websites: https://jordanriverbuffalo.com/* and your github.io address. Paste the key into googleApiKey. Events then appear in the church-styled calendar, on the home page and in pop-ups with “Add to my calendar” buttons. This step is easiest on a computer if you can borrow one.
  5. Optional: put a tag like [youth], [concert], [outreach], [anniversary], [prayer], [bible], [worship] or [special] in an event's description to set its color/category. Otherwise it's guessed from the title.

From then on, adding an event in Google Calendar (including the iPhone Google Calendar app) updates the website automatically. Sample events disappear once the calendar is connected.

7. Announcements & sermon list (free — Google Sheets)

  1. Create a Google Sheet with two tabs: Announcements and Sermons. Use the included template files for the column headings (exact spelling):
    Announcements: Title, Date, Details, Link, Expires
    Sermons: Title, Date, Speaker, Scripture, YouTube Link
  2. Type dates as 2026-12-06 or 12/6/2026. Announcements disappear by themselves after their Expires date.
  3. In Safari (Desktop Website): File → Share → Publish to web → choose the Announcements tab → Comma-separated values (.csv) → Publish → copy the link into announcementsCsv. Repeat for the Sermons tab → sermonsCsv.
  4. From then on, edit the sheet in the Google Sheets iPhone app. The website picks up changes within a few minutes.

Anything in that sheet is public. Never put member contact details or form submissions there.

8. YouTube livestream

  1. Find the channel ID: sign in to YouTube in Safari → go to youtube.com/account_advanced → copy the Channel ID (starts with UC). Paste it into youtube.channelId.
  2. Add the channel link to social.youtube and a broadcast schedule sentence to youtube.broadcastInfo.
  3. Go live from YouTube as usual. The Watch Live page plays whatever is currently live on the channel. (YouTube requires the channel to be verified for live streaming. Live streaming from a phone may have extra YouTube requirements.)
  4. Optional: make a playlist of past services and paste its ID (starts with PL) into sermonsPlaylistId.

9. Online giving

The site never handles card numbers. Visitors go to the provider's secure page. The church chooses a provider. Compare current fees on each provider's own website before deciding:

  • Zeffy — no monthly cost. It says it charges churches no platform or processing fees and is funded by optional donor tips. Requires nonprofit verification and a bank account in the church's name.
  • PayPal (nonprofit/donate button), Tithe.ly, Givelify and others — no monthly subscription required on basic plans, but they charge a fee on each gift.

Once set up, paste the giving link into giving.url (and separate fund links if the provider offers them). Write the provider's own fee wording into giving.feeNote so givers see it, and fill in giving.provider and giving.mailInstructions. Until then, the Give buttons show “Online giving coming soon.”

10. Text-message and email announcements

Free now: the “Text Us” and “Call Us” buttons simply open the visitor's own phone app. They cost the church nothing.

Group text announcements are not free. Sending recurring texts to a list needs a paid texting service. US carriers also generally require business/organization registration (10DLC) for this. When the church is ready:

  1. Choose and set up a texting service. Make sure it handles STOP/HELP replies automatically.
  2. In config.js set textAnnouncementsActive: true and the provider's name. The subscribe form then shows an unchecked opt-in box with consent wording, message frequency, “message and data rates may apply,” and STOP/HELP instructions. No one is ever signed up automatically.
  3. Only text people who checked that box. Keep the submission emails as your record of consent.

Email announcements: subscriptions arrive by email through the form. For a small list, send announcements from the church email using BCC, so members don't see each other's addresses. Always include “Reply UNSUBSCRIBE to stop.” For a larger list, use an email-newsletter service's free tier.

How to edit a file on iPhone

  1. Open your repository on github.com → tap the file (e.g., config.js) → tap the pencil (Edit).
  2. Change only the text between quotation marks. Keep every quote, comma and bracket.
  3. Tap Commit changes. The live site updates in about 1–2 minutes. If something looks wrong, open the file's History to see and undo the change.

Upload a logo or photo

  1. Repository → Add file → Upload files → choose the image → Commit.
  2. Edit config.js: e.g. logo: "logo.png", heroImage: "sanctuary.jpg", pastorPhoto: "pastor.jpg", galleryImages: ["choir.jpg", "outreach.jpg"]. File names must match exactly, including capital letters.

When all the content is in

Set showPlaceholderMarkers: false in config.js to remove the dashed “To be supplied” boxes.

12. Privacy & security practices

  • No administrator pages or submissions are ever on the public website. Submissions go only to the inboxes you choose.
  • Use church-owned accounts (GitHub, Google, Web3Forms, domain) with strong passwords and two-step verification. Give at least two trusted leaders access so the church never gets locked out.
  • Send counseling requests to the pastor's private inbox only. Don't forward them to a group, and delete old requests when they're no longer needed.
  • Restrict the Google API key to the church's web addresses, as described in Section 6.
  • The GitHub repository is public (that's what makes it free). It contains no private data — never upload member lists or submissions to it.

13. Free-tier limits (checked November 2026 — confirm current terms)

  • GitHub Pages: free for public repositories, with automatic HTTPS. Meant for informational sites like this one.
  • Web3Forms free plan: 250 submissions a month, 30 days of submission history, email delivery only. If the church outgrows it, a paid plan or another form service would be needed.
  • Google Calendar API: free with a generous daily quota for a church website.
  • Google Sheets “Publish to web”: free. Changes can take a few minutes to appear.
  • YouTube: free. YouTube's own rules apply to live streaming.
  • Costs not avoidable: the domain name (~$10–11/year), group texting (paid), and payment-processing fees if the chosen giving provider charges them.
